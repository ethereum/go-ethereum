# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## What this is

go-ethereum (geth) is the Go implementation of an Ethereum execution-layer client. It is consensus-critical
software: a behaviour difference from other clients on mainnet is a chain split, not a bug report. Treat
changes under `core/`, `params/`, `consensus/` and `trie/` with that in mind.

Post-merge, geth is the *execution* layer only. Consensus (fork choice, block production timing) lives in a
separate consensus-layer client that drives geth over the Engine API (`eth/catalyst/`).

## Build, test, lint

Everything goes through `build/ci.go`, which the Makefile wraps:

```bash
make geth                       # build just geth into ./build/bin/geth
make all                        # build every command
make test                       # go run build/ci.go test  — the full suite, slow
make lint                       # go run build/ci.go lint  — golangci-lint with the repo config
gofmt -s -w <files>             # note the -s; `make fmt` does this repo-wide
```

For day-to-day work prefer scoping to what you touched — the full suite takes a long time:

```bash
go test ./p2p/...
go test ./core/... -run TestSomething
go vet ./p2p/... ./cmd/...
```

`make lint` is the gate that CI enforces, so run it before proposing a change. It downloads golangci-lint on
first use.

## Conventions that get PRs rejected if ignored

- **Commit subject is `package: lowercase summary`** — `p2p: add SOCKS5 proxy support`, `core/vm: fix gas
  accounting for X`. Multiple packages are comma-separated: `eth/protocols/snap, cmd/devp2p: ...`. No
  trailing period, no capital after the colon. Check `git log --oneline` before writing one.
- **License headers differ by location.** Files under `cmd/` are GPL ("This file is part of go-ethereum");
  everything else is LGPL ("This file is part of the go-ethereum library"). Copy the header from a
  neighbouring file in the same directory rather than from memory — getting this wrong on a new file is a
  guaranteed review comment.
- **`gofmt -s`**, not plain `gofmt`.
- Errors are lowercase and unpunctuated (`errors.New("node does not provide TCP port")`).

## Generated code

Several files are generated and must never be hand-edited. They carry a
`// Code generated by ... DO NOT EDIT.` banner and are produced from a `//go:generate` directive on the type:

- `gencodec` produces JSON/TOML marshalling — e.g. `p2p/config_toml.go` from `p2p/config.go`.
- `rlpgen` produces RLP encoders — e.g. `core/types/gen_log_rlp.go`.

After changing a struct that has a `//go:generate` line, regenerate it:

```bash
go generate ./p2p/          # or whichever package
```

CI fails if the generated output does not match the source.

## Layout

| Path | What lives there |
| --- | --- |
| `cmd/geth` | The geth binary, CLI wiring. `cmd/utils/flags.go` defines every flag and maps it onto config structs. |
| `core/` | State, the EVM (`core/vm`), transaction pool, block processing. Consensus-critical. |
| `eth/` | The `eth` service: protocol handlers (`eth/protocols`), sync (`eth/downloader`), Engine API (`eth/catalyst`). |
| `p2p/` | devp2p: the peer server, RLPx transport, discovery (`p2p/discover`), enode/ENR records (`p2p/enode`). |
| `node/` | Process-level plumbing: service registration, RPC endpoint lifecycle, data directory. |
| `internal/ethapi` | The `eth_*` JSON-RPC implementations. |
| `params/` | Chain configs and fork scheduling. Changes here alter consensus. |

## Networking notes

The p2p stack uses **two transports at once**, and this trips up most networking changes:

- **Discovery is UDP** (`p2p/discover`, discv4 and discv5). It is how the node finds peers *and* how it
  announces its own endpoint to the network.
- **The peer protocol is TCP** (RLPx), dialed by `p2p/dial.go`.

`p2p.Config.Dialer` (a `NodeDialer`) is the extension point for outbound TCP connections; tests use it to
substitute `net.Pipe`. There is no equivalent hook for discovery, because discovery owns its own UDP socket.

Consequences worth remembering:

- Anything that changes how the node reaches the network has to account for both halves. Changing only the
  TCP dialer while discovery keeps running means the node still publishes its real address over UDP.
- A SOCKS5 proxy can carry TCP but not Tor-compatible UDP, which is why `Config.SocksProxy` requires
  `NoDiscovery` and the server refuses to start otherwise (`p2p/socks.go`). Prefer failing loudly over
  silently leaking the node's address.
- Inbound connections are never proxied; `ListenAddr: ""` makes a node dial-only.

## Testing

- Standard `testing`, table-driven where it fits. No assertion library in most packages.
- Prefer real in-process servers over mocks for network code — `p2p/socks_test.go` runs an actual minimal
  SOCKS5 server, `p2p/server_test.go` starts real `Server` instances.
- Mark independent tests `t.Parallel()` and use `t.Cleanup` for teardown.
- Some suites need the consensus test fixtures submodule: `git submodule update --init --depth 1`.

## Scope discipline

This repo has a high review bar and a small maintainer team. Keep a change to one concern, keep it to the
packages named in the commit subject, and do not bundle unrelated refactors, dependency bumps or formatting
sweeps with a functional change — they get sent back. Feature work that changes network or consensus
behaviour usually needs maintainer design buy-in *before* the code, not after.
